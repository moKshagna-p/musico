# Musico mobile

The Android and iOS app, from one Expo (React Native) codebase. Every screen and animation is shared, so a change
lands on both platforms at once; the few platform branches are explicit `Platform.OS` checks.

| Layer | Stack |
| :--- | :--- |
| App | Expo SDK 58, React Native 0.88 (New Architecture), Expo Router |
| Motion | Reanimated 4, Gesture Handler 3, Expo Haptics |
| Input | react-native-keyboard-controller (fields stay above the keyboard), expo-image-picker |
| Data | TanStack Query, Better Auth (Expo client, session in SecureStore) |
| Look | Schibsted Grotesk, expo-image, expo-blur, expo-linear-gradient, react-native-svg |

## Run it

From the repo root, `bun install`, then in `apps/mobile`:

```bash
bun run android   # builds the dev client and installs it on an emulator or device
bun run ios       # same for the iOS simulator (needs Xcode on a Mac)
bun run start     # just the Metro bundler, once a dev client is installed
```

The app talks to `https://musico-web.vercel.app` by default. To use a local API, start it (`bun run dev:api`) and set
`EXPO_PUBLIC_API_URL` before `bun run start`: `http://10.0.2.2:4000` on the Android emulator, `http://localhost:4000`
on the iOS simulator, or your computer's LAN address on a phone.

Signing in needs the API's `expo()` Better Auth plugin and the `musico://` trusted origin (`apps/api/src/auth.ts`).

Logic that has no web-only imports is shared straight from `apps/web` (feed grouping, list rules, profile insights,
artist-name cleanup), so the two never drift.

How the site's motion maps to the app:

- The album cover morph (`utils/morph.js` on the web) is `src/ui/morph.tsx`: the tapped sleeve flies into the album
  page's sleeve with the same 0.8s curve, and back to its tile when you leave.
- Pages fade through like the web's View Transitions; the floating nav (`src/ui/Dock.tsx`) is drawn once above them.
- `whileInView` reveals (rating spread, genre bars, the footer's record) use `useReveal` in `src/ui/scroll.ts`.

`bun run lint` type-checks the app. `android/` and `ios/` are generated by `expo prebuild` and not committed.
